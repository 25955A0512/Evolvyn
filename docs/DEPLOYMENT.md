# Development environment and deployment
Use scripts/install.sh for hash-verified Python dependencies, npm ci, the frontend build, private token generation and PostgreSQL startup. Use scripts/start.sh to start/restart services; live processes are not retained by filesystem publication. The start script recreates setup if the development database container is absent.

Run scripts/backup.sh before publishing or preserving current local data. It atomically writes a mode-0600, ignored .local/database.sql. Installation restores that snapshot only when public.records does not yet exist; an existing database is not overwritten. Snapshot restore was checked in a separate temporary database with matching record counts. This does not establish restoration in a brand-new cloud task; publication and fresh-task restoration remain unverified. Refresh the dump after subsequent work. Uploaded business data in the dump must remain private.

No public deployment has been performed. Before deployment, replace shared-token auth with a real identity provider and tenant authorization, configure authenticated managed PostgreSQL with TLS and versioned migrations, serve built frontend assets through a production HTTPS server and /api proxy, supply secrets through a secret manager, add durable workers, rate/concurrency limits, backups and monitoring. Never deploy the trust-auth local database publicly.

Saved cloud configuration contains installation/startup instructions, network domains api.openai.com and hn.algolia.com and the MODEL_API_KEY requirement. Current research connectivity and local Qwen inference work. No OpenAI key is needed. The old optional OpenAI credential can be removed in environment settings. Review/save the environment draft and publish it to retain the prepared filesystem. A draft save does not itself publish, restart processes or validate fresh-task restoration.

The verified static container profile is `bash scripts/deploy_local.sh`. It uses Nginx, an unprivileged API process, authenticated PostgreSQL, private generated deployment secrets and a provider-health readiness gate when model weights are installed. Local model files and runtime are mounted read-only. `scripts/backup.sh` also preserves Compose data privately, with restore only into an empty schema. Account/record counts matched after a test restore. This is a local deployment, not a public URL or fresh-cloud-task restoration claim.
